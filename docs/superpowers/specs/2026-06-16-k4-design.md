# k4 CLI — Design Spec

_Date: 2026-06-16_

## Context

`k4` is a personal productivity CLI for managing GitHub work using `jj-vcs`. The problem it solves: navigating between multiple active branches/PRs across repos requires too many manual steps (clone, workspace add, bookmark track, cd). `k4` collapses this into a single interactive command, and enriches the shell prompt with PR context. It is built for one user (krakatoa) and optimized for speed and ergonomics over generality.

---

## Tooling

- **Language:** Python 3.14
- **Package manager:** `uv`
- **Lint/format:** `ruff`
- **Type checker:** `pyright` (strict mode)
- **Test framework:** `pytest` + `unittest.mock`
- **CLI framework:** `click`
- **Terminal output:** `rich` + manual OSC 8 escape codes for hyperlinks
- **External binaries required:** `jj`, `gh`, `fzf` (fzf optional; needed for interactive picker)

## Workspace Layout on Disk

```
~/dev/<org>/<repo>/          ← jj repo root (created on first `k4 cd org/repo`)
  .jj/                        ← shared jj state (all workspaces share this)
  .gitignore                  ← workspace dirs added here automatically by k4
  [tracked source files]
  <branch-a>/                 ← jj workspace for branch-a (gitignored)
  <branch-b>/                 ← jj workspace for branch-b (gitignored)
```

Initial clone: `jj git clone <remote-url> ~/dev/<org>/<repo>` (working copy at repo root).  
Each workspace: `jj workspace add <branch>` from the repo root, then `jj bookmark track <remote>/<branch>`.  
k4 appends the workspace directory name to `.gitignore` to prevent it appearing as an untracked change.

## Commands

### `k4 cd [target]` / shell alias `k4d`

**Core mechanic:** `k4 cd` always prints a filesystem path to stdout. The `k4d` shell function wraps it and calls `cd`. This is the standard pattern for shell directory navigation tools.

```zsh
k4d() {
    local target
    target="$(k4 cd "$@")" || return 1
    [[ -n "$target" ]] && cd "$target"
}
```

**Input resolution table:**

| Input | Behavior |
|---|---|
| *(no args)* | Launch fzf over open PRs + personal/starred/forked repos. Selected item resolved per rules below. |
| `123` (integer, inside a jj workspace) | `gh` lookup: if PR #123 exists → open/create workspace for its branch; if no PR → treat as issue (create branch + draft PR for issue #123) |
| `123` (integer, outside any jj workspace) | Error: `"Specify repo: k4 cd org/repo#123"` |
| `org/repo#123` | Treat 123 as issue in org/repo → create branch + draft PR |
| `org/repo` | Open/create workspace for default branch of org/repo |
| `my-branch` | Open/create workspace for that branch in the current repo |

**Workspace creation steps** (when workspace doesn't exist yet):
1. If `~/dev/<org>/<repo>/` doesn't exist: `jj git clone <url> ~/dev/<org>/<repo>`
2. `cd ~/dev/<org>/<repo> && jj workspace add <branch>`
3. `jj bookmark track <branch>@<remote>` (from within the new workspace)
4. Append `<branch>/` to `~/dev/<org>/<repo>/.gitignore`
5. Print `~/dev/<org>/<repo>/<branch>` to stdout

**Issue → Draft PR flow:**
- Fetch issue via `gh issue view <number> --json title,labels`
- Branch name: `{number}-{slugified-title}` (e.g. `42-add-widget-support`, max 60 chars, lowercase, hyphens)
- Guess fix vs implement: if issue has label `bug` → `Fixes #N`, otherwise `Implements #N`
- Create branch: `jj bookmark create <branch-name> -r @`
- Push: `jj git push --bookmark <branch-name>`
- Create draft PR: `gh pr create --draft --title "WIP: <issue title>" --body "Implements #N\n\nCloses #N"`
- Print workspace path

### `k4 .`

Displays current workspace status combining `jj status` and GitHub PR context.

**Output format** (rendered with `rich`, OSC 8 for the URL):

```
● main ← 42-add-widget-support

  📌  PR #123: Add widget support
      https://github.com/acme/myapp/pull/123    ← OSC 8 hyperlink

  🟡 Draft  ✅ CI passing  👁 2 reviewers  🔗 closes #42

  Reviewers:
    ✅  alice      approved
    ○   bob        awaiting review

─────────────────────────────────────────────────────
M src/widget.py
A src/widget_test.py
```

**Data flow:**
1. `jj status` → raw text, displayed below the divider
2. `jj workspace list` → find current workspace and its bookmark
3. `gh pr list --head <bookmark> --json number,title,url,state,isDraft,statusCheckRollup,reviewRequests,closingIssuesReferences` → PR data
4. Render with `rich.console.Console` + `rich.panel` for layout; inject OSC 8 around URL manually

**CI status mapping:**
- All checks pass → `✅ CI passing`
- Any in-progress → `🔄 CI running`
- Any failed → `❌ CI failed`
- No checks → *(omit CI line)*

**No PR found:** displays only `jj status` with a note `No PR found for bookmark <name>`.

### `k4 shell-init [shell]`

Prints the shell integration snippet to stdout. Shell arg: `zsh` or `bash`. User adds to their rc:

```zsh
eval "$(k4 shell-init zsh)"
```

**Snippet defines:**
- `k4d()` function (wraps `k4 cd`)
- `_k4d` completion function (calls `k4 completions "$prefix"`, feeds to shell completion)
- `compdef _k4d k4d` (zsh) or `complete -F _k4d k4d` (bash)

---

### `k4 completions [prefix]`

Returns newline-separated completion candidates for the given prefix. Used by the shell completion function.

Candidates (fetched via `gh`, cached for 60s in `~/.cache/k4/`):
- Open PRs: `123 — Add widget support (acme/myapp)`
- Personal repos: `acme/myapp`
- Starred repos: `other-org/useful-lib`
- Forked repos: `acme/upstream-fork`

Prefix filtering:
- Starts with digit → only PRs
- Contains `/` → only repos matching org/name pattern
- Otherwise → PRs + repos

## Shell Integration Details

**fzf behavior:**
- `k4d` (no args) → `k4 completions | fzf --ansi --preview 'k4 preview {}'` (preview shows PR status)
- If fzf not found → print `"fzf not found. Install with: brew install fzf"` and exit 1
- Tab completion works without fzf

**Completion caching:** `~/.cache/k4/completions.json`, TTL 60 seconds. Avoids hammering the GitHub API on every keypress.

---

## Error Handling

- `gh` not authenticated → friendly message: `"Run: gh auth login"`
- `jj` not found → `"jj not found. Install with: brew install jj"`
- fzf not found → `"fzf not found. Install with: brew install fzf"` (only when interactive picker needed)
- Network errors in `gh` calls → propagate gh's error message, exit 1
- Workspace already exists → silently return its path (idempotent)

## Testing

**Unit tests** (`pytest`): mock `subprocess.run` throughout — all `gh` and `jj` calls are thin wrappers, easily mocked.

Key test areas:
- `workspace.py`: input resolution logic (all table rows above), path construction, idempotency
- `github.py`: JSON parsing from `gh` output
- `display.py`: assert OSC 8 sequences present in output, key strings rendered
- `picker.py`: mock fzf subprocess, verify input/output plumbing

**Type checking:** `pyright --strict src/k4`  
**Lint/format:** `ruff check . && ruff format --check .`  
**CI:** GitHub Actions on push, runs pyright + ruff + pytest

**Manual integration smoke test** (from a real jj workspace with an open PR):
```bash
k4 .             # should show PR info
k4d              # should launch fzf with real PRs
k4d org/repo     # should clone and cd to workspace
```

echo 'eval "$(k4 shell-init zsh)"' >> ~/.zshrc

## Out of Scope (explicit non-goals)

- Multi-user support
- Any UI beyond the terminal
- Notifications or background sync
- Support for non-GitHub remotes (GitLab, Bitbucket)
